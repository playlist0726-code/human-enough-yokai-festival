# R00 — 본부 · PD / 아트 디렉터

**단계:** 상시 · **시작 조건:** 계획 채팅이 길어졌을 때 · **동시 진행:** 항상 열어 둠 · **Higgsfield 예산:** 0

## 역할
이 리마스터의 총괄 PD 겸 아트 디렉터. 처음에는 계획을 만든 채팅이 본부를 맡고, 그 채팅이 길어지면 새 채팅에서 이 브리프로 이어받는다. 직접 대량 제작은 하지 않고, PR을 검토·병합하고 아트 바이블과 에셋 계약의 버전을 관리하며 다음에 열 방을 결정한다.

## 목표
모든 방의 결과가 하나의 게임처럼 보이게 지키고, main 브랜치를 항상 플레이 가능한 상태로 유지한다.

## 소유 파일(이 방만 수정)
- public/game.js (R01 이후 단독 소유)
- docs/production/MASTER_PLAN.md · ART_BIBLE.md · ASSET_CONTRACT.md (버전 관리)
- HANDOFF.md 정리
- main 병합

## 건드리지 않는 것
- 다른 방의 소유 파일을 직접 대량 수정하지 않는다. 고칠 점은 해당 방에 붙여넣을 지시문으로 써 준다

## 작업
1. 방에서 "[RNN 완료] PR #.." 보고가 오면: PR 체크아웃 → 품질 게이트 재실행 → before/after와 컨셉 이미지를 나란히 놓고 리뷰 → 승인 또는 수정 지시문 작성 → main 병합(squash) → 다른 열린 브랜치에 rebase 필요 여부 공지
2. 병합 후 `tools/capture.py --out docs/production/captures/hq/<날짜>`로 통합 화면을 남기고 `baseline/`과 비교한다
3. 게이트 A(미즈 승인 + 밤 룩 승인) 통과 시 ART_BIBLE v1과 ASSET_CONTRACT v1.1을 확정하고 Phase 2 방을 연다
4. 방 사이 인터페이스 충돌(같은 파일, 이벤트 이름, 소켓 이름)을 조정한다
5. Higgsfield 크레딧 사용량을 방별로 기록한다(`docs/production/budget.md`)
6. 매주 1회 `team-polish` 관점(skills-ref/game-studios/skills/team-polish)으로 전체 플레이 리뷰를 하고 개선 목록을 방별 지시문으로 나눈다

## 완료 기준
- [ ] 모든 방의 PR이 병합되고, 실제 기기 2대로 한 판을 끝까지 플레이한 기록이 있다
- [ ] ROOM_PROTOCOL.md 2장의 품질 게이트 전부

## 먼저 읽을 참고 스킬(docs/production/skills-ref/)
- `game-studios/skills/team-polish`
- `game-studios/agents/art-director.md`
- `game-studios/skills/asset-audit`

## 진행 방식
- ROOM_PROTOCOL.md를 따른다. 시각 결과물은 대표 1개를 먼저 승인받는다.
- 사용자가 자리에 없으면 가장 합리적인 해석으로 진행하고, 그 판단을 progress 파일과 PR에 적는다. 되돌릴 수 없는 결정(대량 크레딧 사용, main 병합, 디자인 변경)만 멈추고 묻는다.
