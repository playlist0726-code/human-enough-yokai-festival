# R03 — 캐릭터 파일럿 · 미즈(요괴 + 인간 변장) 완성

**단계:** Phase 1 · **시작 조건:** R01 병합 + 크레딧 충전 · **동시 진행:** R02 · R04 · R05와 동시 · **Higgsfield 예산:** 약 80~120 크레딧(파이프라인 비교 포함 시 최대 200)

## 역할
캐릭터 테크니컬 아티스트(이미지→3D 생성, Blender 리토폴로지·UV·베이크·리깅·애니메이션, glTF).

## 목표
미즈 한 명을 컨셉 시트 수준으로 게임에 넣으면서 **나머지 6명과 NPC가 그대로 따라 할 수 있는 파이프라인**을 확정한다. 이 방의 결과가 Phase 2 전체의 품질 기준이 된다.

## 소유 파일(이 방만 수정)
- source/v2/characters/mizu/*
- source/v2/pipeline/* (신규 공용 스크립트)
- public/assets/models/v2/mizu_*
- public/characters/defs/mizu.json
- public/characters/rig-v2.mjs (R01 이후 캐릭터 런타임 소유)
- public/model-assets.mjs · character-motion.mjs · disguise.mjs · avatar.mjs · visitors.mjs
- docs/production/CHARACTER_PIPELINE.md

## 건드리지 않는 것
- 다른 캐릭터 에셋
- transformation.mjs의 연출(R10)

## 작업
1. 레퍼런스: `public/assets/mizu-reference.png`, `cast.png`의 미즈 열. 같은 디자인으로 **A-pose 정면/측면/후면/3/4 턴어라운드**를 깨끗한 단색 배경으로 만든다(Higgsfield generate_image에 레퍼런스 이미지 입력. 디자인을 바꾸지 않는다)
2. 3D 생성 비교: Tripo H3.1 multiview(18cr)와 Meshy 7(텍스처·PBR, 44cr)을 각각 1회 돌려 실루엣·얼굴·무늬를 비교하고 하나를 고른다. 결과와 비용을 CHARACTER_PIPELINE.md에 기록한다
3. Blender(bpy) 스크립트 `source/v2/pipeline/clean_character.py`: 불필요한 조각 제거 → 25k 삼각형으로 리메시/데시메이트 → 눈을 별도 유광 재질로 분리 → UV → 생성 텍스처를 새 UV에 베이크(baseColor 2048, ORM) → 유카타 무늬와 얼굴을 컨셉 시트와 대조해 보정(필요시 텍스처 페인트 패스)
4. 리깅: Higgsfield `3d_rigging`(8cr) 또는 Blender 자동 웨이트. 계약의 16개 이름으로 바꾸고 `x_dish`, `x_shell`, 소켓 3개를 추가한다. 스크립트 `source/v2/pipeline/rig_contract.py`
5. 애니메이션: 계약의 14개 클립. 기본 이동(idle/walk/run/jump)은 라이브러리 리타깃 또는 키프레임 스크립트로 만들고, 성격 동작(종종걸음, `reveal_panic`, `charm_cast`)은 손으로 다듬는다. 원칙: 예비 동작, 스쿼시·스트레치, 오버슈트
6. 미즈 인간 변장(`mizu_human`, disguise 프로필)과 리빌 소품(`mizu_reveal.glb`: 물접시)을 같은 파이프라인으로 만든다. 인간 기본 몸은 R09가 재사용할 수 있게 `source/v2/characters/human-base/`로 분리한다
7. rig-v2로 게임에 넣는다: 선택 화면, 변신 장면, 필드, 1인칭 손(미니게임) 모두 확인한다. 걸음 속도 동기화, 상체 레이어(걷으며 마시기), 리빌 소켓
8. 사용자 승인용 이미지: 게임 카메라 거리 / 클로즈업 / 컨셉 시트 옆 비교 / 걷기 GIF
9. CHARACTER_PIPELINE.md를 다른 방이 그대로 따라 할 수 있는 수준으로 쓴다(프롬프트 템플릿, 모델 선택 기준, 스크립트 실행 순서, 캐릭터당 실제 크레딧, 자주 생기는 결함과 해결법)
