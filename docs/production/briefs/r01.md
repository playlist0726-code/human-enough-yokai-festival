# R01 — 기반 공사 · 리팩터링과 런타임 v2

**단계:** Phase 0 · **시작 조건:** — (가장 먼저, 혼자) · **동시 진행:** 단독 · **Higgsfield 예산:** 0

## 역할
시니어 그래픽스·엔진 프로그래머(Three.js r180, ES modules, Node 22).

## 목표
여러 방이 동시에 작업해도 충돌하지 않도록 거대한 game.js에서 렌더링·조명·오디오·캐릭터 리그를 분리하고, 새 에셋 규격(v2)을 읽는 런타임과 측정 도구를 만든다. **눈에 보이는 결과와 게임 규칙은 바꾸지 않는다.**

## 작업
1. 사용자가 올린 `remaster-kit.zip`을 풀어 `docs/production/`(문서·briefs·skills-ref·baseline)과 `tools/`(validate-glb.mjs, capture.py)로 커밋한다. 저장소에 이미 있으면 건너뛴다
2. game.js에서 다음을 모듈로 분리한다: 렌더러·후처리·환경맵·안개·조명 → `public/render/pipeline.mjs`, `lighting.mjs`, `post.mjs` / 오디오(AudioContext) → `public/audio/engine.mjs` / 카메라 설정은 기존 free-camera 유지. 분리 전후 스크린샷이 같아야 한다
3. `public/events.mjs`: 게임 이벤트 버스. 서버 스냅샷 차이를 감지해 `potion_pickup, potion_drink, charm_cast, charm_end, reveal_start, reveal_end, cover_ward, guest_delivered, stall_enter, stall_win, stall_fail, hit, sealed, rescued, boss_omen, boss_banished, round_start, round_end, footstep, jump, land, firework` 이벤트를 위치와 플레이어 id와 함께 보낸다. VFX(R10)와 사운드(R13)는 이 버스만 구독한다
4. `public/characters/rig-v2.mjs`: ASSET_CONTRACT의 v2 GLB를 로드한다(GLTFLoader + MeshoptDecoder + KTX2Loader, three/addons 경로를 서버에 등록). AnimationMixer로 클립을 재생하고 크로스페이드하며, 이동 속도에 맞춰 걷기 속도를 동기화하고, 상체 레이어와 소켓 부착을 지원한다. `public/characters/defs/<id>.json`(캐릭터별 v2 경로, 키, 걸음 보정값)이 있는 캐릭터만 v2를 쓰고, 나머지는 기존 rigid 리그로 폴백한다. URL `?rig=legacy`로 강제 폴백
5. `public/perf-overlay.mjs`: `?perf=1`에서 FPS(1% low 포함), draw calls, triangles, geometries, textures, GPU 메모리 추정치, 프로필 이름을 표시한다
6. `scripts/build-production.mjs`에 v2 GLB 압축 단계(@gltf-transform/cli: meshopt, KTX2. toktx가 없으면 WebP 폴백)를 추가한다
7. 테스트: rig-v2의 클립 선택·폴백·소켓 테스트, events 버스 테스트, validate-glb 자체 테스트(tests/fixtures에 최소 GLB)
8. `HANDOFF.md`에 새 모듈 인터페이스(이벤트 이름과 payload, rig-v2 API, defs JSON 스키마)를 문서화한다
