# LIGHTING — 밤 축제 조명 계획 (R02)

> 기준 이미지: `public/assets/submission-cover.png`(키아트), `public/assets/festival.png`(축제 전경).
> 구현: `public/render/*`(조명·하늘·등불 빛·월드 라이트 패치·후처리), `public/visual-quality.mjs`(프로필), `public/art-materials.mjs`(지면 톤).
> 확인 도구: `python3 -I tools/lookdev.py --out <폴더> --profile high|balanced|mobile|light --shots start,street,shrine,wide,fish [--flash] [--perf]`

## 1. 키아트 분석
측정값은 이미지 전체의 휘도(Rec.709) 통계다. `festival.png`는 게임 카메라와 비슷한 높은 사선 구도라서 조명 목표치로 쓴다.

| 항목 | submission-cover | festival.png | 리마스터 전 게임 화면 |
|---|---|---|---|
| 평균 휘도 | 0.43 | **0.29** | 0.54 |
| 어두운 면(휘도 < 0.25) | 35% | **54%** | 7% |
| 밝은 면(휘도 > 0.7) | 22% | 5% | 24% |
| 그림자 평균색 | `#212133` | `#1d212f` | `#2a2528` |
| 중간톤 평균색 | `#98654c` | `#8c615f` | `#677961`(초록) |
| 하이라이트 평균색 | `#eed5a8` | `#f7c78d` | `#d5cebe` |

읽은 것:
- **그림자는 푸른 남색, 중간톤과 하이라이트는 주황·크림.** 화면의 절반 이상이 어둡고, 밝은 곳은 등불 주변뿐이다. 따뜻한 빛과 차가운 그림자의 보색 대비가 핵심이다.
- **빛은 등불에서 나온다.** 길은 등불 아래에서만 따뜻하게 밝고, 등불 사이는 푸른 어둠으로 떨어진다. 빛 웅덩이가 길을 따라 이어진다.
- **달빛은 약한 윤곽광이다.** 키아트의 달은 왼쪽 위에 낮게 떠 있고, 캐릭터와 지붕 가장자리에 차가운 테두리를 남길 뿐 면을 밝히지 않는다.
- **원경은 층층이 흐려진다.** 산 능선 3~4겹이 점점 밝은 남색으로 안개에 묻히고, 호수 마을의 작은 불빛 점들이 원경의 유일한 따뜻한 색이다.
- **포션과 등불만 번진다(블룸).** 다른 면은 번지지 않는다.

## 2. 조명 설계
| 요소 | 값 | 이유 |
|---|---|---|
| 달빛(DirectionalLight, 유일한 그림자) | `#8fa8ff`, 1.05, 방향 (-0.42, 0.78, -0.46) = 북서쪽 위, 고도 약 51° | 오르막 길을 바라보는 기본 카메라에서 달이 앞쪽 왼편에 있어 캐릭터 윤곽과 지붕 가장자리에 차가운 역광이 생긴다. 그림자는 카메라 쪽으로 떨어져 길에 깊이를 준다. 그림자 카메라는 텍셀 단위로 스냅해 걸을 때 떨리지 않는다 |
| 반구광(HemisphereLight) | 하늘 `#4560a8` / 땅 `#4a3326`, 1.45 | 화면 대부분이 이 빛만 받는다. 위는 남색, 아래는 따뜻한 흙색 |
| 환경맵(PMREM) | 남색 하늘 + 지평선의 주황 띠 + 등불 점 9개, 0.55 | 기존 RoomEnvironment(회색 실내)는 밤을 평평하게 만든다. 유광 재질(눈, 포션, 칠기)에 등불 반사가 맺힌다 |
| 따뜻한 바운스(DirectionalLight) | `#ff9a52`, 0.3, 카메라 쪽 앞 | 축제 전체의 등불이 만드는 은은한 반사광 대신. 데몬킹 등장 시 0.6배로 어두워진다 |
| 역광 림(DirectionalLight) | `#7f95ff`, 0.55, 뒤쪽 위 | 실루엣이 길 위에서 떨어져 보이게 한다 |
| 등불 빛 웅덩이(라이트맵) | 등불 앵커마다 반지름 2.6~6 m의 따뜻한 조도를 256×312 텍스처(약 25 cm/px)에 굽는다 | 드로우콜 0개로 길 전체에 빛 웅덩이를 이어 붙인다. 모든 lit 재질이 월드 XZ로 샘플하고, 지면 위 높이(알파 채널에 지면 높이 저장)에 따라 2.2~5.5 m에서 사라진다 |
| 실제 등불 PointLight | 플레이어에게 가까운 등불 앵커를 따라 다님. high 6 · balanced 4 · mobile 2 · light 0 | 캐릭터와 소품에 방향이 있는 따뜻한 빛. 개수가 고정이라 셰이더 재컴파일이 없다. 바뀔 때는 서서히 켜지고 꺼진다 |
| 발광 강화 | 모든 emissive × 1.7 | 등불 종이·포션·간판이 블룸 임계값을 넘도록 |
| 캐릭터 림 | 프레넬 `#a9bcff` 0.55 + 근처 빛 웅덩이 색의 따뜻한 림 | 밤에도 캐릭터가 배경에서 분리된다. 캐릭터(`userData.motionVersion`/`modelAsset`/`volumetric` 표시가 있는 루트)의 재질에만 적용 |
| 안개 | FogExp2 `#1a2547`, 0.0105 + 계곡 안개(높이 1 m 아래로 짙어짐, 최대 0.55) | 원경이 남색으로 묻히고, 산꼭대기 아래 계곡에 푸른 안개가 고인다 |
| 노출 | ACES Filmic, 1.12(light 프로필은 후처리가 없어 1.25) | |

### 하늘과 원경(`render/sky.mjs`, 드로우콜 4개)
- 하늘 돔: 천정 `#070a17` → 위 `#121831` → 지평선 `#2a3a66`. 동쪽(호수·마을 쪽) 지평선에 보랏빛 대기광, 달 주변 헤일로, 구름 띠, 반짝이는 별(셰이더 안에서 해시로 생성).
- 달: 달빛 방향에 놓인 빌보드 원반 + 헤일로. 빛과 그림의 방향이 같다.
- 원경 산 능선 2겹(반지름 175·205 m): 아래는 지평선 안개색, 꼭대기는 달빛을 받은 남색. 동쪽은 낮게 깎아 호수 마을이 보이게 했다.
- 호수 마을 불빛 260개(가산 혼합 포인트, 반짝임). 블룸을 받는다.
- 기존 `festival-scenery.mjs`의 하늘 구·별·달은 제거했다(`REMASTER-HOOK r02`). 산 메시와 호수, 마을 집은 R04 소유로 남는다.

## 3. 후처리 체인(`render/post.mjs`)
장면 → SSAO(high) → 블룸(임계값 0.8, 등불·포션·불꽃만) → Output(ACES + sRGB) → **그레이드**(3D LUT + 비네트 + 불꽃 색광) → SMAA.

그레이드는 화면 공간 함수 `gradeColor()`에서 32³ LUT를 코드로 만든다(파일 로드 없음, 값은 `GRADE`에서 조정).
- 그림자: × (0.62, 0.74, 1.18) 쪽으로 42% — 푸른 섀도
- 하이라이트: × (1.10, 0.96, 0.78) 쪽으로 30% — 따뜻한 하이라이트
- 순수한 초록은 채도를 낮추고 청록으로 기울인다(밤 잔디)
- 채도 1.06, 대비 +10%(피벗 0.36), 블랙 리프트 0.012
- 비네트 0.30(화면 가장자리 약하게)

빛 웅덩이 라이트맵, 하늘, 안개, 림은 모든 프로필에 들어간다(비용이 텍스처 샘플 1번과 몇 개의 연산뿐). 자동 하향은 high → balanced → mobile → light 순서다.

## 5. 불꽃 색광 API
`pipeline.flash(color, intensity=1)` — color는 CSS 색 또는 `THREE.Color`, intensity 0~1.5. 하늘 돔, 원경 능선, 전용 반구광(평소 0), 지면(월드 라이트), 그레이드 패스가 같은 색으로 번쩍였다가 약 0.5초에 걸쳐 사라진다. 여러 번 터지면 가장 강한 것이 이긴다. 현재 `fx/index.mjs`가 불꽃이 터질 때 0.8로 부른다(`REMASTER-HOOK r02`). R10이 새 파티클로 바꿀 때 같은 API를 쓰면 된다.

## 6. 다른 방이 알아야 할 것
- **등불을 만들면 `registerLantern({x,y,z,kind})`를 부른다**(`public/render/lanterns.mjs`, 월드 좌표). kind: `paper`·`stall`·`stone`·`string`·`portal`·`potion`. 그러면 빛 웅덩이와 실제 빛이 자동으로 생긴다. 환경 코드에서 PointLight를 직접 만들지 않는다.
- 발광 재질은 emissive로 만들면 된다. 파이프라인이 밤에 맞게 1.7배로 올리고 블룸을 준다. 등불·포션이 아닌 면에 강한 emissive를 쓰지 않는다.
- 캐릭터 루트에 `userData.motionVersion` 또는 `modelAsset`이 있으면 림 라이트가 자동으로 붙는다(R03·R06~R09). 캐릭터 재질은 림용 사본으로 바뀐다.
- `?perf=1` 수치의 draw calls에는 후처리 패스가 포함된다.

## 7. 성능 영향(룩뎁 시작 지점, 1280×720, 같은 구도)
소프트웨어 WebGL 샌드박스라 FPS는 재지 않았다. draw calls(후처리 패스 포함)·삼각형·켜진 조명 수는 하드웨어와 무관하다.

| 프로필 | draw calls 전 → 후 | 삼각형 전 → 후 | 켜진 조명 전 → 후 |
|---|---|---|---|
| high | 3,484 → 3,655 | 11.07 M → 11.60 M | 10 → 10 |
| mobile | 2,140 → 2,222 | 6.73 M → 7.04 M | 10 → **6** |
| light | 1,626 → 1,631 | 5.09 M → 5.09 M | 10 → **4** |

- 늘어난 draw calls는 하늘 4개와 달빛 방향이 바뀌며 그림자 패스에 들어오는 물체가 늘어난 몫이다. 빛 웅덩이는 드로우콜이 없다.
- 노점마다 있던 PointLight 6개(강도 16)를 없애고 프로필별 개수(6·4·2·0)로 바꿔서, 모든 lit 픽셀이 계산하는 조명 수가 mobile·light에서 줄었다.
- 모든 프로필이 계약 예산(high ≤250 / mobile ≤150 draw calls)을 크게 넘는 것은 R01 기준치와 같은 원인(기존 모델·장식)이다. R04(환경 재제작)와 R14가 줄인다.
